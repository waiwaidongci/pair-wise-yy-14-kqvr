# 木构榫卯测绘复核台

古建筑木结构榫卯构件的测绘建档、换人复核、节点校核与修缮任务工作台。数据保存在浏览器 localStorage，刷新后状态一致。

## 业务规则

### 建档（建筑 / 轴线 / 构件编号）
录入木材、榫型、截面（宽×高）、朝向、含水率、病害类型与范围。

### 硬性红线 —— 命中任一条只能进入「待复核」
1. 编号重复（同一建筑 + 同一轴线 + 同一构件编号）
2. 截面尺寸非正（宽或高 ≤ 0）
3. 含水率 > 18%
4. 损伤贯穿截面

待复核构件：不生成关系边（节点为 blocked 阻断状态）、不生成修缮任务。

### 换人实测复核
复核人必须与建档人不同，由复核人现场填写实测截面、含水率与病害范围；
修正后仍不满足红线的构件继续留在待复核。

### 节点冻结
节点两端榫型不同、截面不同、朝向不相对（东—西 / 南—北）即冻结：
- 冻结节点以红边显示，其两端构件的修缮任务冻结；
- 经共用构件与冻结节点连通的下游节点链上修缮任务一并冻结（下游传播，阻断节点不传播）；
- 节点每次状态变更（含删除）自动留档，旧版保留。

### 级联重算
所有节点状态、修缮任务、统计指标均为纯函数派生：上游构件一改录，
构件清单 / 关系图 / 待办 / 统计立即按新值重算，刷新后保持一致。

## 页面

- **构件建档与复核**：新增建筑/构件、榫型与状态筛选、问题清单、改录、换人复核弹窗
- **节点与关系图**：按建筑的 SVG 构件关系图（相符绿边 / 冻结红边 / 阻断灰虚线）、建前对照、节点台账
- **修缮待办**：待办 / 冻结 / 已完成分组，冻结原因与上游节点
- **留档审计**：节点状态时间线、构件逐版本字段 diff

## 技术栈

React 19 + Vite + TypeScript（无后端，localStorage 持久化）

## 本地运行

```bash
npm install
npm run dev        # http://localhost:62013
npm run selftest   # 51 项领域规则自测
npm run build
```

开发端口：62013

## 代码结构

```
src/domain/
  types.ts       领域类型
  constants.ts   榫型/朝向/病害字典、18% 红线、对向关系
  derive.ts      纯函数派生：构件校验 → 节点判定 → 冻结传播 → 任务 → 统计
  seed.ts        两栋古建筑演示数据
src/store.tsx    操作 API（建档/改录/复核/建节点/删除/任务完成）+ 留档 + 持久化
src/components/  MembersPage / NodesPage / TasksPage / ArchivePage
scripts/selftest.ts  业务不变量自测
```
